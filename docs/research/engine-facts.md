# Engine facts: Phaser vs Godot

Research note for [Engine facts: Phaser vs Godot](https://github.com/NikosZisisPD/collaboard/issues/3). It feeds [Choose the engine: Phaser or Godot](https://github.com/NikosZisisPD/collaboard/issues/7), so it reports facts and trade-offs, not a verdict.

- **Versions covered**: Phaser **4.2.1**, the latest stable release ([2026-07-09](https://github.com/phaserjs/phaser/releases/tag/v4.2.1)), and Godot **4.7.2**, the latest stable release ([2026-08-18](https://github.com/godotengine/godot/releases/tag/4.7.2-stable)). Godot docs links point at the version-pinned `/en/4.7/` pages; source links are pinned to the release tags.
- **Checked on** 2026-09-23 against official docs, release notes, source code and specs. Figures marked *measured* were measured from the official release artifacts, with the method given alongside.
- **Not covered here**: which model to run, structured replies, and which tokenizer meters the Prompt Budget. Those belong to [LLM facts: local model calls and Prompt token counting](https://github.com/NikosZisisPD/collaboard/issues/4). This note covers the engine side of each question.

## Summary

| | Phaser 4.2.1 | Godot 4.7.2, web export |
|---|---|---|
| What it is | A JavaScript library with bundled TypeScript types, running inside your page | An engine and editor app that exports a WebAssembly build |
| Start and reload | `npm run dev`: Vite on `localhost:8080`, reloads the tab on save | Editor button "Run in Browser": exports and serves on `localhost:8060`; re-export by hand after changes |
| Install for a browser build | `npm install` | The editor (171 MB download) plus the Web export templates (10–12 MB each) |
| Engine payload | `phaser.min.js`: 1.38 MB, 352 KB gzipped | `godot.wasm`: 39.5 MB, 10.1 MB gzipped, plus the game's `.pck` |
| Threads and special headers | None needed | Single-threaded by default, no special headers; threads need COOP/COEP headers |
| Calling Ollama | The browser's `fetch`, streaming available | `HTTPRequest`/`HTTPClient`, built on `fetch`; docs say no chunked responses |
| Calling a JS tokenizer | A normal `import` | `JavaScriptBridge`, web builds only; the library has to be put into the page |
| Prompt text box | An HTML `<textarea>`, over the canvas or in a React/Vue page | A `TextEdit` node drawn in the canvas, or HTML in a custom page |
| Platformer physics | Arcade (boxes and circles, `pushable` bodies) or Matter.js | `CharacterBody2D` plus `RigidBody2D` crates |
| Tile maps | Tiled JSON, CSV, 2D arrays; no LDtk support | Built-in `TileMapLayer` editor; Tiled via Tiled's own exporter; LDtk via community plugins |
| Language | TypeScript or JavaScript, types bundled | GDScript (gradually typed); C# can't be exported to the web |

## 1. Browser tab on localhost

### Phaser

- Phaser is an npm package under the MIT license, installed with `npm install phaser` ([v4.0.0 release notes](https://github.com/phaserjs/phaser/releases/tag/v4.0.0), [package.json](https://github.com/phaserjs/phaser/blob/v4.2.1/package.json)).
- The official scaffolder is `npm create @phaserjs/game@latest`, an interactive CLI with templates for Vue, React, Angular, Next.js, Svelte and plain bundlers, "most of these come in both JavaScript and TypeScript versions". It points first-time users to "Web Bundler", then "Vite" ([create-game README](https://github.com/phaserjs/create-game/blob/0b3db61f0cd51d88b0ce2a0e949a99ec471bd976/README.md)).
- **Start command and reload on save**: in the official Vite + TypeScript template, `npm run dev` serves the game on `http://localhost:8080`. After you edit a file in `src`, "Vite will automatically recompile your code and then reload the browser" ([template README](https://github.com/phaserjs/template-vite-ts/blob/d1d7d58acfcf47f97642bcb8b4967071b85f8db9/README.md); port in [`vite/config.dev.mjs`](https://github.com/phaserjs/template-vite-ts/blob/d1d7d58acfcf47f97642bcb8b4967071b85f8db9/vite/config.dev.mjs)). The template is "updated for Phaser 4": it pins `phaser` 4.0.0, Vite ^6.3.1 and TypeScript ~5.7.2 ([package.json](https://github.com/phaserjs/template-vite-ts/blob/d1d7d58acfcf47f97642bcb8b4967071b85f8db9/package.json)).
- `npm run dev` also runs `log.js`, which "makes a single silent API call to a domain called `gryzor.co`" (owned by Phaser Studio), sending the template name, dev or prod, and the Phaser version. `npm run dev-nolog` skips it ([template README, "About log.js"](https://github.com/phaserjs/template-vite-ts/blob/d1d7d58acfcf47f97642bcb8b4967071b85f8db9/README.md#about-logjs)).
- **No special headers**: nothing in Phaser 4.2.1's `src/` references `SharedArrayBuffer` (searched), so the cross-origin isolation question below doesn't come up.
- **Payload** (*measured* from the `phaser@4.2.1` npm tarball, compressed with `gzip -9`): `dist/phaser.min.js` is 1,375,976 bytes (352,455 gzipped). The Arcade Physics build, which "excludes Matter.js physics" ([entry point](https://github.com/phaserjs/phaser/blob/v4.2.1/src/phaser-arcade-physics.js#L13)), is 1,266,396 bytes as `dist/phaser-arcade-physics.min.js` (319,752 gzipped).
- Phaser pauses its game loop while the page is hidden ([`Game#onHidden`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Game.js#L561-L575)).

### Godot

- **Browser requirements**: WebAssembly and WebGL 2.0, and web builds can only use the Compatibility renderer. "Safari has several issues with WebGL 2.0 support that other browsers don't have", so the docs recommend a Chromium-based browser or Firefox ([Exporting for the Web: WebGL version](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#webgl-version)).
- **What you install**: the editor app, plus export templates, which "must be installed to export projects" through **Editor > Manage Export Templates** ([Exporting projects: Export templates](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_projects.html#export-templates)).
  - The 4.7.2 macOS editor download (universal zip) is 170,622,178 bytes ([release assets](https://github.com/godotengine/godot/releases/tag/4.7.2-stable)). Homebrew's `godot` cask is also at 4.7.2 ([formulae.brew.sh](https://formulae.brew.sh/cask/godot)).
  - Since 4.7 the template manager installs individual templates ([GH-117072 in the changelog](https://github.com/godotengine/godot/blob/4.7.2-stable/CHANGELOG.md?plain=1#L1194)), so you no longer need the all-platform bundle, which is 1,281,349,702 bytes (1.28 GB) for 4.7.2 ([release assets](https://github.com/godotengine/godot/releases/tag/4.7.2-stable)). The eight Web template zips inside that bundle are 10.2–12.1 MB each (*measured* by reading the bundle's zip directory over HTTP range requests).
- **Start command**: with a Web export preset and templates in place, a button appears in the editor toolbar "to quickly open the game in the default browser for testing" ([Export options](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#export-options)).
  - Its menu offers "Run in Browser" and "Start HTTP Server", then "Re-export Project" and "Stop HTTP Server" while the server runs ([source](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/export/export_plugin.cpp#L703-L707)).
  - "Run in Browser" exports a **debug** build into the editor's temp folder and opens `http://localhost:8060/tmp_js_export.html` in the system's default browser ([source](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/export/export_plugin.cpp#L851-L883)). The host and port default to `localhost` and `8060` ([export.cpp](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/export/export.cpp#L45-L47)).
- **Reload on save**: not for the web build. The editor doesn't re-export when you save; the "Re-export Project" option exists to "Export project again to account for updates" ([source](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/export/export_plugin.cpp#L741-L745)). The editor's server sends `Cache-Control: no-store`, so refreshing the tab picks up a new export ([source](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/export/editor_http_server.cpp#L108-L115)).
  - Live reload does exist when the game runs **natively** from the editor. With **Synchronize Script Changes** on, "any changes made to the script in the editor will be reloaded in the running project" ([Debugging tools](https://docs.godotengine.org/en/4.7/tutorials/scripting/debug/overview_of_debugging_tools.html#synchronize-script-changes)). A native run isn't the browser, though: `JavaScriptBridge` isn't available there (section 3).
- **From the command line**: `godot --headless --path <project> --export-debug <preset> <path>` exports without opening the editor, given a preset in `export_presets.cfg` and installed templates ([Command line tutorial](https://docs.godotengine.org/en/4.7/tutorials/editor/command_line_tutorial.html#exporting)). Any static server can then serve the files. The docs suggest the Godot repo's [`serve.py`](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/serve.py) for local testing ([Serving the files](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#serving-the-files)); it defaults to port 8060 and opens `http://127.0.0.1:8060`.
- **Threads and cross-origin isolation headers**: "Since Godot 4.3, Godot supports exporting your game on a single thread", and the docs call it "the preferred and now default way to export your games on the Web" ([Exporting for the Web](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html)). **Thread Support** defaults to off in the source ([export_plugin.cpp](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/export/export_plugin.cpp#L374-L375)).
  - With **Thread Support** on (and likewise **Extensions Support**, for GDExtension), the files must be served with `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` from a secure context; otherwise "the project will not run" ([Thread and extension support](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#thread-and-extension-support), [Serving the files](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#serving-the-files)). A Progressive Web App option can simulate those headers with a service worker (same page).
  - Without threads, the build is "more prone to performance and audio issues, but will only require to be run on an HTTPS website" ([`variant/thread_support`](https://docs.godotengine.org/en/4.7/classes/class_editorexportplatformweb.html#class-editorexportplatformweb-property-variant-thread-support)), and `localhost` "is usually exempt" from the HTTPS requirement ([Limitations](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#limitations)).
  - The editor's own server sends the COOP and COEP headers (and `Access-Control-Allow-Origin: *`) on every response, whatever the thread setting ([source](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/export/editor_http_server.cpp#L108-L115)). That matters for loading JavaScript libraries (section 3).
- **C# on the web**: "Projects written in C# using Godot 4 currently cannot be exported to the web", and the docs suggest Godot 3 for C# on the web ([Exporting for the Web](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html), [C# platform support](https://docs.godotengine.org/en/4.7/tutorials/scripting/c_sharp/index.html#c-platform-support)).
- **Build size** (*measured* from `templates/web_nothreads_release.zip` in the 4.7.2 bundle, compressed with `gzip -9`): `godot.wasm` is 39,514,754 bytes (10,054,758 gzipped) and `godot.js` is 279,815 bytes (68,471 gzipped). The game's own `.pck` comes on top. This matches the docs, which say the WebAssembly module compresses "down to around a quarter of its original size with gzip" ([Serving the files](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#serving-the-files)). A custom-compiled template with unused features disabled can shrink it ([Mobile considerations](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#mobile-considerations)).
- The browser pauses the project while its tab isn't the active tab ([Background processing](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#background-processing)).

## 2. Calling a local model over HTTP

These facts apply to both engines:

- A page on `http://localhost:8080` and Ollama on `http://localhost:11434` are different origins, because the port is part of the origin ([MDN: Same-origin policy](https://developer.mozilla.org/en-US/docs/Web/Security/Same-origin_policy)), so the browser applies CORS ([Fetch Standard: CORS protocol](https://fetch.spec.whatwg.org/#http-cors-protocol)).
- Ollama v0.34.3 (the latest release, 2026-09-19) allows these origins by default: `http://localhost`, `http://localhost:*`, `http://127.0.0.1:*` and `http://0.0.0.0:*` (plus the `https` variants), and `app://*`, `file://*`, `tauri://*`, `vscode-webview://*` and `vscode-file://*`. `OLLAMA_ORIGINS` adds to this list rather than replacing it ([envconfig/config.go](https://github.com/ollama/ollama/blob/v0.34.3/envconfig/config.go#L85-L109)).
  - The server matches that list with wildcards and allows the `Content-Type` header that a JSON `POST` needs ([server/routes.go](https://github.com/ollama/ollama/blob/v0.34.3/server/routes.go#L1858-L1888)).
  - So both engines' default dev servers are allowed without setting `OLLAMA_ORIGINS`: `localhost:8080` for the Phaser template, and `localhost:8060` or `127.0.0.1:8060` for Godot. The LLM facts ticket covers the Ollama side in depth.
- Chrome's Local Network Access permission doesn't come into play: "Requests originating from the loopback address should not be considered local network requests", and Chromium currently enforces it only for requests from public sites ([WICG: Local Network Access](https://wicg.github.io/local-network-access/)).
- Ollama streams replies by default. With `"stream": false`, the reply is "a single response object" ([Ollama API docs, chat endpoint](https://github.com/ollama/ollama/blob/v0.34.3/docs/api.md?plain=1#L512)).

### Phaser

- Game code runs in the page, so it calls Ollama with the browser's own `fetch`. A streamed reply can be read chunk by chunk from `response.body` ([MDN: Using readable streams](https://developer.mozilla.org/en-US/docs/Web/API/Streams_API/Using_readable_streams)).
- Optionally, Vite's `server.proxy` forwards requests whose path starts with a given prefix to another server during development ([Vite: server.proxy](https://vite.dev/config/server-options#server-proxy)). That makes the Ollama calls same-origin, which takes CORS out of the picture.

### Godot (web export)

- The `HTTPRequest` node "is the easiest way to make HTTP requests in Godot" and is backed by `HTTPClient` ([Making HTTP requests](https://docs.godotengine.org/en/4.7/tutorials/networking/http_request_class.html)). It delivers the whole reply at once through its `request_completed` signal ([HTTPRequest](https://docs.godotengine.org/en/4.7/classes/class_httprequest.html#class-httprequest-signal-request-completed)), and "you have to wait for a request to finish before sending another one" on the same node ([Making HTTP requests](https://docs.godotengine.org/en/4.7/tutorials/networking/http_request_class.html)).
- In a web export, `HTTPClient` is built on the browser's `fetch()` ([library_godot_fetch.js](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/js/libs/library_godot_fetch.js#L80-L100)), so browser rules apply. The class reference warns that the server "may not allow requests from foreign origins due to CORS" ([HTTPClient](https://docs.godotengine.org/en/4.7/classes/class_httpclient.html)).
- The docs list these web restrictions on the HTTP classes: no access to the `StreamPeer`, no threaded or blocking mode, a request "cannot progress more than once per frame", "No chunked responses", host verification can't be disabled, and the same-origin policy applies ([Networking](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#networking)). The body length is always `-1` on the web ([`get_response_body_length`](https://docs.godotengine.org/en/4.7/classes/class_httpclient.html#class-httpclient-method-get-response-body-length)).
- **Docs and source disagree on streaming.** The 4.7.2 source reads the `fetch` body with a stream reader and hands chunks to `read_response_body_chunk()` as they arrive ([response handling](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/js/libs/library_godot_fetch.js#L47-L69), [read loop](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/js/libs/library_godot_fetch.js#L117-L134)). So `HTTPClient` may be able to show a streamed Ollama reply as it arrives, but I didn't test it, and the docs say otherwise. `HTTPRequest` waits for the whole body either way.
- Another route is calling `fetch` from GDScript through `JavaScriptBridge` and binding a callback to the returned Promise with `.then(...)`, as the docs' Notification example does ([Callbacks](https://docs.godotengine.org/en/4.7/tutorials/platform/web/javascript_bridge.html#callbacks)).
- With **Thread Support** on (COEP `require-corp`), `fetch` in `cors` mode is still allowed: "requests made in cors mode won't be blocked by COEP or trigger COEP violations, but must still be permitted by CORS" ([MDN: COEP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cross-Origin-Embedder-Policy)). Godot's own description of that option warns cross-origin isolation is "limited for security reasons (such as not being able to communicate with third-party websites)" ([`variant/thread_support`](https://docs.godotengine.org/en/4.7/classes/class_editorexportplatformweb.html#class-editorexportplatformweb-property-variant-thread-support)). I didn't test this against Ollama.
- The class reference scopes its CORS warning to "a project exported to Web" ([HTTPClient](https://docs.godotengine.org/en/4.7/classes/class_httpclient.html)). A native run from the editor doesn't behave like the browser build here.

## 3. Calling a JavaScript library, such as a tokenizer

### Phaser

- The Phaser templates are ordinary Vite projects (the template "uses Vite for bundling", [template README](https://github.com/phaserjs/template-vite-ts/blob/d1d7d58acfcf47f97642bcb8b4967071b85f8db9/README.md)). A tokenizer from npm is imported and called like any other module, in the same page as the game and the Prompt text box.

### Godot (web export)

- The `JavaScriptBridge` singleton "is implemented only in the Web export". Official export templates ship with it enabled, and custom builds can leave it out ([JavaScriptBridge](https://docs.godotengine.org/en/4.7/classes/class_javascriptbridge.html)).
- `JavaScriptBridge.get_interface("name")` wraps a property of `window` as a `JavaScriptObject`, whose methods you call like a Godot object's. Ints, floats, strings and booleans convert automatically ("floats might lose precision when converted from Godot to JavaScript"); objects, arrays and functions stay wrapped ([Interacting with JavaScript](https://docs.godotengine.org/en/4.7/tutorials/platform/web/javascript_bridge.html#interacting-with-javascript)).
- Calls from JavaScript back into Godot need `JavaScriptBridge.create_callback()`. You must keep a reference to the callback, and it takes exactly one `Array` argument ([Callbacks](https://docs.godotengine.org/en/4.7/tutorials/platform/web/javascript_bridge.html#callbacks)). `eval()` returns numbers as `float`, plus booleans, strings and byte buffers; "any other JavaScript value is returned as `null`" ([The eval interface](https://docs.godotengine.org/en/4.7/tutorials/platform/web/javascript_bridge.html#the-eval-interface)).
- **Getting the library into the page**: the docs use **Head Include** (appended to the page's `<head>`) or a **Custom HTML shell**, and their example adds a `<script>` from a CDN ([Can I use my favorite library?](https://docs.godotengine.org/en/4.7/tutorials/platform/web/javascript_bridge.html#can-i-use-my-favorite-library), [Export options](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#export-options)).
- **In the editor's dev loop**, the one-click server only serves the exported files, by name, from its temp folder, and only these file types: `html`, `js`, `json`, `pck`, `png`, `svg` and `wasm` ([request handling](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/export/editor_http_server.cpp#L88-L103), [file types](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/export/editor_http_server.cpp#L246-L252)). It also always sends COEP `require-corp` (section 1).
  - So a library file sitting in your project folder isn't served. You can inline the library's code in Head Include or the shell, or load it from a CDN whose response permits it.
  - Under `require-corp`, a cross-origin script needs a `Cross-Origin-Resource-Policy` header or a CORS request ([MDN: COEP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cross-Origin-Embedder-Policy)). jsDelivr, used in the docs' example, sends `cross-origin-resource-policy: cross-origin` (checked with `curl -I` on 2026-09-23). A CDN does need internet access during the demo.
- **Outside the browser**, "on platforms other than HTML5, calling `JavaScriptBridge.eval` will also return `null`", which is why the docs check `OS.has_feature('web')` first ([The eval interface](https://docs.godotengine.org/en/4.7/tutorials/platform/web/javascript_bridge.html#the-eval-interface)). A JavaScript tokenizer therefore can't count Prompt tokens when the game runs natively from the editor. That takes the browser build or a GDScript tokenizer (the LLM facts ticket covers GDScript options).

## 4. A text box for Prompts

### Phaser

- Phaser 4.2.1 has no text-input Game Object (none among `src/gameobjects`, searched). Its DOM Element docs name native HTML as the way to add "a text input box for a highscore table" ([DOMElement](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/domelement/DOMElement.js#L76-L80)).
- **Option A, a DOM Element over the canvas**: `this.add.dom(...)` places an HTML element over the game canvas that you position like a Game Object. It needs `dom: { createContainer: true }` and a `parent` in the game config ([DOMElement](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/domelement/DOMElement.js#L17-L38)).
  - Since Phaser 4, a DOM Element without a container throws an error ([migration guide](https://github.com/phaserjs/phaser/blob/v4.2.1/changelog/v4/4.0/MIGRATION-GUIDE.md?plain=1#L383-L386)).
  - DOM Elements sit above or below the canvas and can't be layered between sprites. They "cannot be enabled for input" either: you attach native listeners with `addListener` ([DOMElement](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/domelement/DOMElement.js#L59-L66)).
- **Option B, HTML outside the canvas**: a `<textarea>` in the page, or in a React or Vue component. The official React and Vue templates (both on Phaser 4.0.0) include an `EventBus` "to communicate between React and Phaser" ([template-react-ts README](https://github.com/phaserjs/template-react-ts/blob/c7265972c856906cacf1f2892d8565d64a358d34/README.md)).
- **Keyboard capture gotcha**: by default, Phaser "will not stop the event from propagating up to the browser", and captures are global across Scenes ([`addCapture`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardPlugin.js#L244-L251)).
  - `addKey` and `addKeys`, however, default to `enableCapture=true`, which calls `preventDefault` ([source](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardPlugin.js#L486-L493)). `createCursorKeys()` registers Up, Down, Left, Right, Space and Shift that way ([source](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardPlugin.js#L393-L411)).
  - So a Scene that calls `createCursorKeys()` would stop Space and the arrow keys from reaching a textarea. `disableGlobalCapture()` exists for cases where "you swap to a DOM element" ([source](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardPlugin.js#L360-L374)).
  - The player never controls a character ([ADR 0001](../adr/0001-prompt-only-play.md)), so the game may not need key captures at all.

### Godot

- `TextEdit` is "a multiline text editor" (its class keyword is `textarea`) with a `text_changed` signal ("Emitted when the text changes"), a `placeholder_text` property and a line-wrapping mode ([TextEdit](https://docs.godotengine.org/en/4.7/classes/class_textedit.html#class-textedit-signal-text-changed)). A `Label` beside it can show the live count.
- On the web, Godot draws everything inside a `<canvas>` ([EditorExportPlatformWeb](https://docs.godotengine.org/en/4.7/classes/class_editorexportplatformweb.html)). Clipboard sync "requires a browser supporting the Clipboard API" and "might not be reliable when accessed from GDScript" ([Clipboard](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#clipboard)).
- Alternatively, an HTML `<textarea>` can go in a custom HTML shell, which is "mostly a regular HTML document" ([Custom HTML page](https://docs.godotengine.org/en/4.7/tutorials/platform/web/customizing_html5_shell.html)), and GDScript reads it through `JavaScriptBridge`. The same docs page notes that "the game itself cannot easily be directly controlled from the outside yet".
- In a web build, the live counter would call the tokenizer through `JavaScriptBridge` on every `text_changed` (section 3).

## 5. 2D platformer basics

### Phaser

- **Arcade Physics** "provides a lightweight, fast AABB (axis-aligned bounding box) and circle-based collision system suited for most 2D game needs" ([ArcadeSprite](https://github.com/phaserjs/phaser/blob/v4.2.1/src/physics/arcade/ArcadeSprite.js#L14-L15)). A body's geometry "is always an axis-aligned rectangle or a circle" ([Body](https://github.com/phaserjs/phaser/blob/v4.2.1/src/physics/arcade/Body.js#L234)).
  - **Walking and jumping**: `body.onFloor()` returns `blocked.down` ([Body](https://github.com/phaserjs/phaser/blob/v4.2.1/src/physics/arcade/Body.js#L1697-L1706)).
  - **Pushing boxes**: `pushable` "Sets if this Body can be pushed by another Body", and "By default, Dynamic Bodies are always pushable". `immovable` controls "Whether this Body can be moved by collisions with another Body" ([Body](https://github.com/phaserjs/phaser/blob/v4.2.1/src/physics/arcade/Body.js#L637-L664)).
- **Matter.js** physics is also bundled, for rigid bodies, compound bodies and constraints ([Phaser's physics-matter skill](https://github.com/phaserjs/phaser/blob/v4.2.1/skills/physics-matter/SKILL.md)).
- **Tile maps**: the supported formats are CSV, Tiled JSON, 2D arrays and Weltmeister (Impact.js) ([Formats.js](https://github.com/phaserjs/phaser/blob/v4.2.1/src/tilemaps/Formats.js)).
  - Collision can be set by tile index, by a tile property set in Tiled, or from Tiled's collision shapes. The Tiled parser doesn't support "Collection of Images" tilesets ([Phaser's tilemaps skill](https://github.com/phaserjs/phaser/blob/v4.2.1/skills/tilemaps/SKILL.md)).
  - Phaser 4 adds `TilemapGPULayer`, which renders "an entire tilemap layer as a single quad" ([v4.0.0 release notes](https://github.com/phaserjs/phaser/releases/tag/v4.0.0)).
- **Editors**: Tiled's own docs list Phaser among the JavaScript frameworks that load Tiled maps ([Tiled: Support for TMX maps](https://doc.mapeditor.org/en/stable/reference/support-for-tmx-maps/)).
  - There's no LDtk code in Phaser 4.2.1 (searched), and LDtk's own list of loaders has no Phaser entry, only generic JS/TS loaders ([LDtk: loading LDtk files](https://ldtk.io/api/)).
  - LDtk's "Super simple export" writes PNG images plus a CSV file per IntGrid layer ([LDtk docs](https://ldtk.io/docs/game-dev/super-simple-export/)), and CSV is one of Phaser's formats. I didn't test that combination.

### Godot

- `CharacterBody2D` bodies "are not affected by physics at all, but they affect other physics bodies in their path", and `move_and_slide()` provides wall and slope detection ([CharacterBody2D](https://docs.godotengine.org/en/4.7/classes/class_characterbody2d.html#class-characterbody2d-method-move-and-slide)). The editor's built-in "Basic Movement" script template for it applies gravity with `get_gravity()`, jumps only when `is_on_floor()`, and moves left and right from input actions ([basic_movement.gd](https://github.com/godotengine/godot/blob/4.7.2-stable/modules/gdscript/editor/script_templates/CharacterBody2D/basic_movement.gd)).
- `RigidBody2D` is described as "useful for objects that can be interacted with in an environment, such as a tree that can be knocked over or a stack of crates that can be pushed around", and `apply_central_impulse()` pushes one from code ([RigidBody2D](https://docs.godotengine.org/en/4.7/classes/class_rigidbody2d.html)).
  - `move_and_slide()` reports what it hit through `get_slide_collision()` ([Using CharacterBody2D](https://docs.godotengine.org/en/4.7/tutorials/physics/using_character_body_2d.html)).
  - The docs don't say how strongly a `CharacterBody2D` pushes a `RigidBody2D` crate on its own (see the open questions).
- **Tile maps**: `TileMapLayer` nodes let you paint tiles on a grid and "add collision, occlusion, and navigation shapes to tiles", and terrains connect neighbouring tiles automatically ([Using TileMaps](https://docs.godotengine.org/en/4.7/tutorials/2d/using_tilemaps.html)). `TileMapLayer` was exposed in Godot 4.3 ([4.3 changelog](https://github.com/godotengine/godot/blob/4.3-stable/CHANGELOG.md?plain=1#L109)), and the older `TileMap` node is deprecated: "Use multiple `TileMapLayer` nodes instead" ([TileMap](https://docs.godotengine.org/en/4.7/classes/class_tilemap.html)).
- **Tiled**: since version 1.10, Tiled "ships with a plugin to export maps" to Godot 4 `.tscn` files ([Tiled: Godot 4 export](https://doc.mapeditor.org/en/stable/manual/export-tscn/)).
  - In Tiled 1.12.2 that exporter writes a `TileMap` node ([source](https://github.com/mapeditor/tiled/blob/v1.12.2/src/plugins/tscn/tscnplugin.cpp#L929)), the deprecated type.
  - Godot's TileMap panel can extract it into `TileMapLayer` nodes ([TileMap](https://docs.godotengine.org/en/4.7/classes/class_tilemap.html)).
- **LDtk**: LDtk's list of loaders has three community Godot importers, one of them for Godot 4 ([LDtk: loading LDtk files](https://ldtk.io/api/)).
- **Editor activity**: LDtk's latest release is v1.5.3, from 2024-01-15 ([release](https://github.com/deepnight/ldtk/releases/tag/v1.5.3)). Tiled's is v1.12.2, from 2026-05-27 ([release](https://github.com/mapeditor/tiled/releases/tag/v1.12.2)).

## 6. Ramp-up for a TypeScript developer

### Phaser

- **Language and typings**: you write TypeScript or JavaScript. The npm package bundles its own type definitions (`"types": "./types/phaser.d.ts"`) and ships ESM and CommonJS builds in its `exports` map ([package.json](https://github.com/phaserjs/phaser/blob/v4.2.1/package.json)).
- **Tooling**: npm, Vite and the TypeScript templates from section 1, including React and Vue versions ([create-game README](https://github.com/phaserjs/create-game/blob/0b3db61f0cd51d88b0ce2a0e949a99ec471bd976/README.md)).
- **Phaser 4 is recent**: 4.0.0 shipped on 2026-04-10 as "a ground-up rebuild of the WebGL renderer ... while keeping the API you know and love" ([v4.0.0 release notes](https://github.com/phaserjs/phaser/releases/tag/v4.0.0)). The v3-to-v4 migration guide has 21 sections, mostly about rendering: pipelines, filters, tint, cameras and shaders, and the Canvas renderer is deprecated. Physics and tilemaps have no section of their own ([migration guide](https://github.com/phaserjs/phaser/blob/v4.2.1/changelog/v4/4.0/MIGRATION-GUIDE.md)).
- **For AI-assisted coding**: the repository and npm package include 28 skill folders for AI coding agents, covering Phaser's subsystems and the v3-to-v4 migration ([v4.0.0 release notes](https://github.com/phaserjs/phaser/releases/tag/v4.0.0), [skills/](https://github.com/phaserjs/phaser/tree/v4.2.1/skills)).

### Godot

- **Language**: GDScript is "a high-level, object-oriented, imperative, and gradually typed programming language built for Godot", with "an indentation-based syntax similar to languages like Python", though it "is entirely independent from Python" ([GDScript reference](https://docs.godotengine.org/en/4.7/tutorials/scripting/gdscript/gdscript_basics.html)).
  - Static types are optional. Turning on the `UNTYPED_DECLARATION` warning makes them mandatory ([Static typing: warning system](https://docs.godotengine.org/en/4.7/tutorials/scripting/gdscript/static_typing.html#warning-system)).
  - `await` works on signals and coroutines ([Awaiting signals or coroutines](https://docs.godotengine.org/en/4.7/tutorials/scripting/gdscript/gdscript_basics.html#awaiting-signals-or-coroutines)).
- **C#** needs the separate .NET build of the editor, and C# projects can't be exported to the web ([C#/.NET](https://docs.godotengine.org/en/4.7/tutorials/scripting/c_sharp/index.html)).
- **TypeScript**: no official support. The third-party GodotJS project adds "TypeScript/JavaScript Support for Godot 4.x" and describes itself as "essentially usable but still under testing" ([GodotJS README](https://github.com/godotjs/GodotJS)). It ships its own editor builds and export templates, and its macOS app isn't signed ([GodotJS: Getting started](https://godotjs.github.io/documentation/getting-started/)).
- **Tooling**: scenes, tile sets and exports live in the Godot editor. For code in an external editor:
  - The official VS Code extension is `godot-tools` ([Official editor plugins](https://docs.godotengine.org/en/4.7/tutorials/editor/external_editor.html#official-editor-plugins)). Version 2.7.1 is also published on Open VSX ([Open VSX](https://open-vsx.org/extension/geequlim/godot-tools)).
  - Completion and debugging come from Godot's LSP (port 6005) and DAP (port 6006) servers, which need the Godot editor running on the project ([LSP/DAP support](https://docs.godotengine.org/en/4.7/tutorials/editor/external_editor.html#lsp-dap-support)).
  - **Auto Reload Scripts on External Change** reloads scripts edited outside the Godot editor ([Automatically reloading your changes](https://docs.godotengine.org/en/4.7/tutorials/editor/external_editor.html#automatically-reloading-your-changes)).

## Open questions / couldn't verify

- **Streaming in a Godot web build**: the docs say the web HTTP classes have "No chunked responses", but the 4.7.2 source reads replies incrementally (section 2). Untested. It only matters if the Companion should show its reply while it streams in.
- **How pushing a box feels**: Phaser documents `pushable`, and Godot documents what `CharacterBody2D` and `RigidBody2D` are for, but neither says how box pushing behaves with default settings. A short spike in either engine would answer it.
- **Godot web start-up and export times**: not measured, because this ticket was research only and no Godot project was built. Unknowns: the `.pck` size for a handful of Levels, how long "Re-export Project" takes, and how fast a 39.5 MB `godot.wasm` starts on the M4 Pro.
- **Cost of `JavaScriptBridge` per keystroke**: the docs say nothing about the speed of calling a JavaScript tokenizer on every `text_changed`.
- **Threaded Godot build calling Ollama**: MDN says CORS-mode requests pass under COEP `require-corp`, and Ollama answers CORS for localhost origins, but I didn't test it.
- **Safari**: Godot's docs recommend Chromium or Firefox over Safari for WebGL 2.0, and "Run in Browser" opens the system's default browser. Not tested on the dev machine.
- **Phaser's docs site**: `docs.phaser.io` refused automated requests (HTTP 403), so Phaser facts are cited from its source code and first-party skill files at the `v4.2.1` tag instead.
- **Not checked**: whether the community Tiled and LDtk importers for Godot work with 4.7, and visual editors such as Phaser Editor.
